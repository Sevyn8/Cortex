## §1 Overview

F05 ships the **Schema Evolution Engine** — the substrate, classifier, history API, and CI gate for tracking and gating schema changes across the platform. Every schema change is classified `ADDITIVE` / `BREAKING` / `DEPRECATION`; breaking changes require Super Admin approval in non-dev environments; historical schema versions are retrievable as of any date.

Three scope axes per build-prompt §F05:

1. **Change Classification** — automated classifier diffs two schema versions and proposes `ADDITIVE` / `BREAKING` / `DEPRECATION`. CI check ensures every migration declares its classification; non-dev breaking changes are blocked without approval.
2. **Schema Versioning** — every entity type semver-versioned. Tenant pins to a major; minor + patch auto-rollout. Version history queryable via API + surfaced in SCR-07 (later).
3. **Feature Store Integration** — when a feature's input schema changes, F05 notifies A01 to trigger feature re-computation OR invalidate stale features. **Hook stubbed in Phase 1; full A01 integration is Phase 2** per roadmap §4.7.

**Phase 1 deliverables (this module):**

- Bi-temporal `schema_definition` substrate (D1) on F03's `cortex_scd_trigger` foundation.
- `@cortex/schema-evolution` workspace package (D11) with module discipline per future-roadmap §1.17.
- Classifier engine over Drizzle pgTable + Zod schemas as D01-future proxies (D3).
- Semver versioning + history API (D2).
- 5 new audit verbs (D9; F04 Slice D's `CONFIG_PROMOTE_BLOCKED` REJECT precedent).
- CI check (GHA pre-merge + Cloud Build pre-deploy defense-in-depth, D6).
- A01 notification stub throwing `FeatureStoreNotImplementedError` (D8; F04 Slice E precedent).
- AC01 approval surface stub: env-aware throw `SuperAdminApprovalRequiredError` in non-dev (D7).

**Phase 2 deferrals (explicit boundary per D12):**

- Full A01 Feature Store wire (D8 stub remains until A01 ships).
- Full AC01 Super Admin approval enforcement (D7 stub remains until AC01 ships per roadmap §1.17 access-control plan).
- D01-shaped entity types as the schema source of truth (D3 proxy until D01 ships in P3.1).

**Module-close commit:** `feat(F05): schema evolution engine` per build-prompt line 1205.

## §3 D-locks

Twelve cross-cutting decisions analogous to F04's D1-D14. Locked at module-scoping PR (this PR); each slice's HOLD #1 may add `Q-NEW-F05<slice>-N` items.

### D1 — Storage substrate: bi-temporal `schema_definition`

**Locked:** `schema_definition` table with the bi-temporal pattern (`cortex.cortex_scd_trigger` + `tstzrange` columns + GiST index per ADR-DB-001). Columns include `id`, `tenant_id`, `entity_type`, `version` (semver), `definition_json` (Drizzle/Zod-shaped), `classification` (`ADDITIVE`/`BREAKING`/`DEPRECATION`), `valid_time`, `txn_time`, audit metadata.

**Rationale:** Acceptance criterion 3 (historical schema retrievable as of any date) is bi-temporal-shaped; using F03's substrate makes it trivial. Bi-temporal also provides the audit-friendly "what did the schema look like 6 months ago" queries the spec implies.

**Alternatives rejected:**

- **Append-only log table** — would still need per-entity-type latest projection; bi-temporal subsumes both with first-class history-as-of-date queries.
- **Per-tenant `schema_definition` separate from canonical** — premature multi-tenancy split; classifier should run against the canonical schema; tenant pinning is a metadata column on the same row.

### D2 — Schema versioning scheme: semver

**Locked:** Semver (`major.minor.patch`) per build-prompt directive ("every D01 entity type is semver-versioned"). Three explicit columns OR single string column with parsing helpers — Slice B HOLD #1 picks (Q-NEW-F05B-N).

**Rationale:** Build-prompt is explicit. Tenant-pins-to-major + auto-rollout for minor + patch is the standard semver dependency model.

**Alternatives rejected:**

- **Monotonic int + classification flag** — loses the major/minor distinction that auto-rollout depends on.
- **Content-hash versioning** — impossible to determine pin order or auto-rollout direction.

### D3 — Schema-shape source of truth: Drizzle pgTable + Zod proxies for D01-future entities

**Locked:** Phase 1 F05 operates on **Drizzle pgTable + Zod schemas** as proxies for D01 entity types until D01 ships. Classifier diff input accepts either shape; `registerSchemaEvolutionEntity` adapter normalizes to the substrate's `definition_json` form.

**Rationale:** D01 (Canonical Model) is Phase 3 unshipped (P3.1). Build-prompt scope item 2 says "every D01 entity type is semver-versioned" — Phase 1 cannot deliver this against an entity type system that doesn't exist. Using Drizzle pgTable + Zod schemas as proxies preserves the F05 contract; the substrate's `entity_type` column is a string identifier that survives the eventual D01 migration.

**Migration path:** When D01 ships, F05's proxy registration migrates to D01-shaped entity types via a follow-on schema migration. The `definition_json` column accommodates both shapes by virtue of being JSONB.

**Alternatives rejected:**

- **Wait for D01 to ship** — blocks F05 indefinitely; F04 module close already unblocked the module queue.
- **F05 invents its own entity-type system** — duplicates D01's eventual canonical model; violates DRY at the platform level.

### D4 — Diff mechanism: reuse F04 Slice D's `diffJson` + extend

**Locked:** F05's classifier reuses `diffJson` from `@cortex/config-plane`'s `impact-analysis.ts` for the structural diff layer. F05 adds a schema-aware classifier on top: column-add → ADDITIVE; column-rename or column-drop → BREAKING; column-mark-deprecated (presence of `deprecated: true` flag) → DEPRECATION.

**Rationale:** `diffJson` is already battle-tested (28 tests in F04 Slice D); its bidirectional path-matching semantics fit schema-shape diffs naturally. Building a from-scratch differ duplicates work.

**Module-discipline note (D11):** `@cortex/schema-evolution` core domain MUST NOT import from `@cortex/config-plane`. The classifier consumes `diffJson` via an adapter at `services/schema-evolution-service/` (or similar) that imports both. This preserves D11's portability discipline.

**Alternatives rejected:**

- **Zod-semantic schema-shape diff** (deep schema comparison) — complex; first-consumer-deferred. Phase 1 structural-diff covers the common cases.
- **Custom AST differ** — overkill for Phase 1.

### D5 — Classification declaration syntax: header comment

**Locked:** Migration files (SQL or Drizzle-kit-emitted) declare classification via header comment:

```sql
-- @schema-classification: ADDITIVE
-- ... migration body
```

Allowed values: `ADDITIVE`, `BREAKING`, `DEPRECATION`. Mandatory on every migration; Slice C CI check enforces presence + value.

**Rationale:** Mirrors F03 Slice A's `-- @bi-temporal: skip` directive precedent (CLAUDE.md `### Bi-temporal table convention`). Header comments are language-agnostic, parseable by simple grep, and don't require a sibling file (which would drift).

**Alternatives rejected:**

- **Sibling `<migration>.classification.json` file** — drift risk; pairs of files harder to keep in sync.
- **Drizzle-kit metadata extension** — couples to Drizzle's internal API; brittle.

### D6 — CI check integration: GHA pre-merge + Cloud Build pre-deploy

**Locked:** Two enforcement layers (defense-in-depth):

1. **GHA workflow step** before the existing `Run foundation tests against ephemeral Postgres` check — fails the PR if any new/modified migration lacks a classification header OR has an invalid value.
2. **Cloud Build pre-deploy verification** in `infra/cloud-build/migrate.yaml` — fails the deploy if a migration is `BREAKING` and the env is non-dev without an explicit approval marker (D7 stub provides this in Phase 1; AC01 wires the real flow in Phase 2).

**Rationale:** GHA catches at PR-time (cheapest); Cloud Build catches at deploy-time (last line of defense). Both layers needed because GHA can be bypassed via admin override (though branch protection blocks this per CLAUDE.md `### Why no admin bypass`); Cloud Build runs against the actual env.

**Alternatives rejected:**

- **Pre-commit hook only** — too easy to skip locally.
- **Cloud Build only** — misses the PR-time signal; bad CI experience.

### D7 — AC01 dependency: env-aware approval-stub

**Locked:** `assertCanPromoteBreaking(ctx, env)` is env-aware:

- **Dev:** allow (return without throwing). Acceptance criterion 1 holds.
- **Non-dev:** throw `SuperAdminApprovalRequiredError` carrying classification details + would-be-required role (`SUPER_ADMIN` per build-prompt). Phase 2 wires the real role check via `@cortex/access-control` adapter; Phase 1 stub demonstrates the block.

**Rationale:** Build-prompt explicitly distinguishes dev (deploy without approval) from non-dev (require approval). Env-aware stub captures both cases without depending on AC01. The Phase 2 wire-up is a thin adapter swap.

**Alternatives rejected:**

- **Always-allow stub** — violates acceptance criterion 2.
- **Always-throw stub** — violates acceptance criterion 1; blocks dev velocity.

### D8 — A01 dependency: throw NotImplementedError

**Locked:** `notifyFeatureStore(ctx, schemaChange)` throws `FeatureStoreNotImplementedError` with message referencing roadmap §4.7 + Phase 2 trigger conditions. Mirrors F04 Slice E's `GitSyncNotImplementedError` shape (Q-NEW-F04E-2 precedent).

**Rationale:** Silent no-op masks the deferral and creates surprise when A01 ships. Throw signal is loud and clear; callers (when wired) get the hook-not-implemented error.

**Alternatives rejected:**

- **Silent no-op** — rejected by F04 Slice E precedent.
- **Pub/Sub topic emit** — premature substrate; no consumer yet.

### D9 — Audit catalog: 5 new verbs

**Locked:** `@cortex/schema-evolution` registers 5 verbs at module init via `registerAuditActions([...])`:

1. `SCHEMA_REGISTERED` (CREATE) — first-time entity-type registration.
2. `SCHEMA_CLASSIFIED` (READ) — classifier ran; outcome captured in payload.
3. `SCHEMA_PROMOTED` (CREATE) — new schema version landed.
4. `SCHEMA_DEPRECATED` (UPDATE) — entity-type marked DEPRECATION.
5. `SCHEMA_BREAKING_BLOCKED` (REJECT) — non-dev breaking-change attempt blocked. F04 Slice D's `CONFIG_PROMOTE_BLOCKED` precedent (audit-on-error in fresh transaction per F04 Slice D's separate-transaction pattern).

**Rationale:** F04's catalog discipline (one catalog per module) extends here. REJECT verb pattern from F04 Slice D normalizes the block-path audit for compliance.

### D10 — Test substrate: reuse `@cortex/test-db-harness`

**Locked:** `@cortex/test-db-harness` (carved out at F03 Slice B B.0) is the canonical test-DB harness; F05 reuses it. New schema-fixture helpers extend the harness as needed (analogous to F04 Slice C's `cleanupConfigPlaneState` extension).

**Rationale:** No reason to fork; harness is the workspace-wide convention.

### D11 — Package shape + module discipline

**Locked:** New workspace package `@cortex/schema-evolution` at `/packages/schema-evolution/`. Module-discipline guardrails per future-roadmap §1.17 — applied analogously to F05's substrate vs the Cortex-specific integrations:

- **Core domain logic** in `packages/schema-evolution/src/` MUST NOT import from `@cortex/*` packages directly. Classifier, diff-extension, version helpers, substrate readers — all standalone.
- **Cortex-specific integrations** (F02 audit emission via `@cortex/audit-events`, F04 config reads via `@cortex/config-plane`, F03 history queries via `@cortex/temporal-query`, RLS context binding) live in adapter modules under `services/schema-evolution-service/` or as a sibling `packages/schema-evolution-cortex-adapters/` package.

**Note:** §1.17's wording targets AC01-AC04 specifically, but the operator's broader rule ("module discipline preserves ~80% of future extraction value at ~5% cost") applies equally to F05. Slice A HOLD #1 confirms the exact adapter location.

**Rationale:** Same as §1.17 — disciplined boundaries preserve future-extraction optionality at minimal cost.

**Alternatives rejected:**

- **Embed in `@cortex/canonical-schema`** — entangles schema-evolution with the Drizzle schema definitions; violates SRP.
- **No discipline** — cheaper now but compounds future cost if extraction ever needed.
